# Documentation

User-facing guides are Jekyll markdown in `docs/` (published to rocketjob.reidmorrison.com; the CNAME is `docs/CNAME`). Edit these for behavior/usage doc changes.

**The look and feel is not in this repo.** `docs/_config.yml` sets `remote_theme: reidmorrison/rm-docs-theme@v1`, and the layout, stylesheet, sidebar, syntax highlighting and Mermaid loader all come from there. This repo holds only its content: the markdown pages and `docs/images`. **Do not add a `docs/_layouts` or `docs/stylesheets` directory** - they were deleted deliberately, because six gem repos each carried a near-identical copy of the same theme and the copies had drifted. A styling change belongs in `rm-docs-theme`, where it reaches every doc site at once. `v1` is a moving major tag, so theme fixes arrive on the next build; breaking changes go to `v2` and are opted into by editing the pin. `jekyll-remote-theme` must stay in `plugins`: GitHub Pages enables it on its own, but a local build does not, and without it every page silently renders with no layout.

Serve locally against the published theme with `cd docs && bundle exec jekyll serve`, or against a local theme checkout with `~/src/rm-docs-theme/bin/preview ~/src/rocketjob/docs`.

**Navigation and page titles are config, not markup.** The sidebar is the `nav` block in `docs/_config.yml`; adding or renaming a page means editing it there. A page's title lives in its front matter (`title:`), and the theme renders it as the page's `h1`. `index.md` sets `heading:` instead so the home page keeps the tuned SEO `<title>` from `_config.yml`.

Docs conventions (learned writing `index.md`):
- Markdown is **kramdown** (`_config.yml`). A page opens with `**Contents**` and a `* TOC` / `{:toc}` block, with no heading above it: the page title comes from front matter and the theme renders the `h1`. The old idiom put a `{:.no_toc}` `##` heading there, which would now produce two titles. `toc_levels` is `2..3`, so `####` and deeper stay out of the contents card. `docs/index.md` and the sibling `semantic_logger/docs/index.md` are the model for a prose landing page.
- Code fences use `~~~ruby` / `~~~bash` / `~~~yaml` (tildes), not triple backticks.
- **Write examples for people learning the API, not compressed like source code** (2026-10). A block that does work gets `do ... end` with its body on its own line, nested blocks are never on one line, `obj.tap { ... }.save!` chains become plain build, upload and save steps, and schema hashes put one field per line. One-line idioms readers expect stay: lambda defaults (`default: -> { Date.today }`), Minitest `let`, and a simple trailing `if`. Long single calls with nothing nested (such as `Logger.publish(...)` or `secret_config.fetch`) may stay on one line.
- **Mermaid diagrams** (added 2026-06): use a `~~~mermaid` tilde fence (kramdown treats it as a code block, so the source survives even if JS does not render). A page that contains a diagram **must** add `mermaid: true` to its YAML front matter; that flag is what makes the shared theme load Mermaid (v10 ESM from jsDelivr). The loader now lives in `rm-docs-theme`'s `_includes/mermaid.html`, not in this repo. It converts kramdown's rendered fence into a `div.mermaid` and handles both output shapes (the rouge wrapper `div.language-mermaid` and a bare `code.language-mermaid`), so do not change the `.language-mermaid` selector lightly. It also picks the diagram palette from the resolved page theme rather than hard-coding `neutral`, which is what stops a white diagram glowing on the dark ground. Diagrams present: simple-job state machine + batch sub-state (`before`/`processing`/`after`) lifecycle (derived from `lib/rocket_job/plugins/job/state_machine.rb` and `lib/rocket_job/batch/state_machine.rb`), and the slice fan-out / simple-job queue `flowchart`s on `index.md`/`batch.md`. Keep diagram facts in sync with those state machines.
- Cross-page links are plain inline relative links to the rendered `.html` (e.g. `[Batch Guide](batch.html)`, `mission_control.html`, `dirmon.html`, `guide.html`, `installation.html`). Some older pages use reference-style `[text][1]` footers instead; either is fine, prefer inline for new prose.
- External canonical links (all doc sites moved off `rocketjob.io` to `*.reidmorrison.com` in 2026-08; do not reintroduce `rocketjob.io`): this site `https://rocketjob.reidmorrison.com`, `https://logger.reidmorrison.com` (Semantic Logger), `https://config.reidmorrison.com` (Secret Config), `https://encryption.reidmorrison.com` (Symmetric Encryption), `https://iostreams.reidmorrison.com` (IOStreams), MongoDB `https://mongodb.com`. Each sister project's own `docs/CNAME` is the authority for its hostname; the subdomain does not always match the gem name (`semantic_logger` -> `logger.`, `secret_config` -> `config.`, `symmetric-encryption` -> `encryption.`).
- Prefer the doc site over the GitHub repo when linking a sister project that has one: IOStreams and Symmetric Encryption prose links were switched from `github.com/reidmorrison/*` to their doc sites (2026-08).
- Sister-project GitHub links (for projects without a doc site: sync_attr, active_record_slave) use the current maintainer org `github.com/reidmorrison/*`. Several older pages still link `github.com/rocketjob/*`; GitHub redirects those, but prefer `reidmorrison` for new/edited links. Not yet normalized site-wide (potential future cleanup).
- Mission Control screenshots live under `docs/images/rjmc/` in per-area subdirectories (`jobs/`, `job/`, `servers/`, `dirmon/`, plus `workers.png`); reference with `![alt](images/rjmc/jobs/running.png "title")`. The flat `rjmc_*.png` names this file used to list do not exist.
- Field declaration syntax in all current docs/tests is `field :name, type: String` (Mongoid form). The old `index.md` used the bare `field :login, String` form; do not copy it.
- `guide.md` (Programmer's Guide) was rewritten (2026-06) to match that style and use the kramdown auto-TOC idiom (replacing the hand-maintained `#### Table of Contents` list). Every section was verified against `lib/rocket_job/`. Corrections future doc edits must not regress: the CLI has **no `--filter`** (it is `--include` / `--exclude` regexp + `--where` JSON, plus the `--list`/`--stop`/`--kill`/`--pause`/`--resume`/`--dump`/`--refresh` server-management commands; default worker count is **10**, from `Config.max_workers`). Keep repeated "Example" blocks as bold prose, not headings, so they stay out of the generated TOC.
- `batch.md` (Batch Guide) was rewritten (2026-06) the same way. **Decision: keep `guide.md` (simple jobs) and `batch.md` (batch jobs) as two separate pages** — do not merge; `guide.md` has no batch code to move out (only one cross-link to batch in its Transactions section). Verified the batch API against `lib/rocket_job/batch/` + `lib/rocket_job/category/`. Bugs fixed in the old page that must not regress: `RocketJob::Batch::Result.new` takes **category first, then value** (the old `Result.new(line, :invalid)` was backwards; correct is `Result.new(:invalid, line)`); the slice throttle is `throttle_running_workers` (per-job-instance, `0`/`nil` = unlimited, default nil) — distinct from the simple-job `throttle_running_jobs`; every batch example needs `include RocketJob::Batch` (an old `TabularJob` omitted it). Category serializers: Input allows `:none`/`:compress`(default)/`:encrypt`; Output also `:bz2`/`:encrypted_bz2`. Output `nils` defaults to `false` (skip nil results). Batch callbacks: `before/after/around_slice` + `before_batch`/`after_batch` (async; no `around_batch`); custom batch throttles via `define_batch_throttle`.
- **Encryption/compression positioning (2026-06).** There are **two independent** encryption layers, do not conflate them in docs: (1) batch **slice serializers** (`input_category`/`output_category serializer: :encrypt`), opt-in per job, encrypt the sliced data at rest in `rocketjob_slices`; (2) **field-level** `field :ssn, type: String, encrypted: true` on **any** job (batch or simple), provided by symmetric-encryption's Mongoid extension (`../symmetric-encryption/lib/symmetric_encryption/railties/mongoid_encrypted.rb`), transparent encrypt-on-write / decrypt-on-read. **Compression is the default** (`:compress` serializer); **encryption is always opt-in** — never describe encryption as a default. Compression is **not** only from symmetric-encryption: the `:compress` serializer uses Zlib, symmetric-encryption does compress-then-encrypt on the `:encrypt` path, and IOStreams handles file-level formats (`.gz`/`.zip`/`.bz2`) on `upload`/`download`. `index.md` sells this under the "Compressed by default, encrypted when you need it" reasons bullet plus an "Encrypt a sensitive field" feature-tour section (with the `field ..., encrypted: true` example); `batch.md` "Compression and encryption" frames the storage/bandwidth + compliance benefit. Selling points: reduced storage/network bandwidth (compression) and compliance/at-rest protection of sensitive data (encryption).
- `advanced.md` was rewritten and **renamed to `architecture.md`** (2026-06) as an "Architecture and Internals" page (concurrency/thread model, MongoDB in-place processing + `find_and_modify`, reliability/requeue, scalability, and the plugin-composition architecture). The old `advanced.html` URL is preserved via `redirect_from: /advanced.html` front matter, which needs the `jekyll-redirect-from` plugin (now enabled in `docs/_config.yml plugins:`; it ships in the `github-pages` gem but is opt-in). The sidebar entry is "Architecture" -> `architecture.html`, in the `nav` block of `docs/_config.yml`. Its programmer-facing content was **moved into `guide.md`**: a new **Thread Safety** section (`guide.html#thread-safety`) and **Extending Jobs with Plugins** section (`guide.html#extending-jobs-with-plugins`). Cross-page kramdown anchors are relied upon (e.g. `architecture.html#the-job-is-a-composition-of-plugins`); keep those headings stable. **The class diagram and architecture overview now live here, moved out of `CONTRIBUTING.md` (2026-06)**: `architecture.md` gained "Public vs internal API", "Batch jobs and slices", "Runtime: Supervisor, Server, Workers", and the Mermaid **class diagram** (`#class-diagram`, linked from the page intro). `CONTRIBUTING.md`'s Architecture section is now just a pointer to `architecture.html`, except **"Adding a job plugin" stays only in `CONTRIBUTING.md`** (contributor mechanics). The simple-job lifecycle section in `guide.md` documents the bang vs non-bang transitions (`abort` mutates in memory, `abort!` also persists; `whiny_persistence`).

Supported-version sources (always re-derive from these files, not from memory):
- **Ruby**: `.github/workflows/ci.yml` test matrix. JRuby support is implied by the `:jruby`-platform gems in `Appraisals`.
- **Mongoid + Rails/ActiveRecord**: the `Appraisals` file. Generated gemfiles + locks are in `gemfiles/`.
- **MongoDB server**: not pinned by rocketjob; it follows whatever the active Mongoid version supports. Mongoid 8.1–9.1 currently support MongoDB server 3.6–8.x (per the Mongoid README / compatibility matrix).
